## 一、AI 评论分析

在 Amazon 商品详情页打开卖家精灵插件并进入【AI 评论分析】，有两个报告入口：

| 入口 | 位置 | 定位 | 主要内容 | 阅读成本 |
|---|---|---|---|---|
| **生成 AI 分析报告** | Amazon 详情页内的插件 | 简版评论速读 | 评论总结、Alexa 原声、首页评论原声 | 较低 |
| **生成卖家精灵分析报告** | 跳转卖家精灵网页版 | 多维度深度分析 | 评论概况、星级分布、变体数据、评论类型、变化趋势等 | 更完整 |

> 想快速看懂口碑 → 用【生成 AI 分析报告】；想看更完整数据与趋势 → 用【生成卖家精灵分析报告】。

### 1. 生成 AI 分析报告（插件简版）

**分析逻辑**：买家评论 + Amazon Alexa for Shopping 的 6 个固定买家口碑问题 → AI 归纳整理。

包含三个固定页签：

#### ① 评论总结（默认页签）

先展示买家口碑速读与评论概况，再用 6 张固定卡片归纳核心反馈：

| 卡片 | 回答的问题 |
|---|---|
| 好评亮点 | 买家最认可产品的哪些方面？ |
| 差评痛点 | 买家集中抱怨哪些问题？ |
| 买家期待 | 买家希望产品在哪些方面改进？ |
| 人群画像 | 评论中出现了哪些典型使用人群？ |
| 使用场景 | 买家通常在什么情况下使用产品？ |
| 购买理由 | 买家为什么选择购买这个产品？ |

**按目的选读**：
- 竞品调研 → 优先【差评痛点】+【买家期待】；
- 分析目标用户 → 优先【人群画像】+【使用场景】；
- 研究购买动机 → 优先【购买理由】+【好评亮点】。

#### ② Alexa 原声

展示 Amazon Alexa for Shopping 针对该产品的 **6 个固定买家口碑问题**（可切中文译文）：
1. 买家最喜欢产品的哪些方面；
2. 差评主要在抱怨什么；
3. 哪些人群或使用场景更适合；
4. 哪些人群或情况可能不适合；
5. 买家使用后希望哪些地方得到改进；
6. 买家认为产品是否物有所值。

⚠️ **Alexa 原声不是某位买家发布的原始评论**，而是 Amazon 购物助手基于平台信息生成的口碑回答（可能结合 Listing 标题、五点描述等页面信息），只能作为**补充视角**。

#### ③ 首页评论原声

展示当前 Amazon 商品页可获取的真实 Review：评论星级、标题、正文、日期、已验证购买标识、"有帮助"数量、评论图片。

**何时必须回看原声**：
- 发现严重产品质量问题；
- 好评与差评存在明显分歧；
- 某个问题可能只出现在特定型号；
- 需确认买家具体使用方式；
- 需判断一条反馈是否具有代表性。

### 2. 生成卖家精灵分析报告（网页版深度）

可查看：
- Listing 及变体的评论数量；
- 各变体评分与评论分布；
- 评论星级与评分星级结构；
- VP 评论、图片评论、视频评论、Vine 评论等类型；
- 不同时间范围的评论变化；
- 不同变体的评论数量与趋势；
- 消费者画像、使用场景、产品优缺点、未满足需求、购买动机。

**关键区分**：
- **评分星级占比** = 各星级 Rating 数量 / 总评分数；
- **评论星级统计** = 各星级文字 Review 数量 / 总评论数。

> 当**低星文字评论占比较高**时，说明买家能在商品页看到较多具体负面反馈 → 应进评论列表确认差评集中在哪些问题。

**评论型号统计**：对比不同变体（尺寸/颜色/子 ASIN）在指定时间范围内的评论数量及占比。

⚠️ 评论数据存在**留评率与时间延迟**，且受上架时间、变体合并、促销活动影响。备货时仍需结合实际订单、销量、库存、退货率与供应周期判断。

### 3. 应用场景

| 场景 | 做法 |
|---|---|
| 快速了解产品 | 【生成 AI 分析报告】依次看：好评亮点 → 差评痛点 → 买家期待 → 人群画像/使用场景 → 购买理由 |
| 批量初筛多个竞品 | 先用插件简版报告记录每个竞品的核心好评/高频差评/使用场景/人群/购买理由/未满足需求 → 横向对比筛出重点竞品 |
| 深入研究重点竞品 | 两种报告结合：先答"买家在说什么"，再看评论分布、低星是否集中、变体评论差异、评论类型 |
| 找产品开发与改进方向 | 用【差评痛点】+【买家期待】发现反复提及的问题（尺寸描述不准、舒适度不足、材质/耐用性、操作不清、包装配件不全、不适合特定人群）→ 进原声看语境 → 决定改产品/改尺寸/补说明/优化包装/Listing 提前说明 |
| 优化 Listing 减少预期偏差 | 结合差评痛点 + 买家期待 + 原声，检查买家是否误解尺寸、不清楚适用场景、图片未展示关键细节、五点遗漏限制、对材质颜色配件预期错误 → 优化标题/图片/五点/A+/尺寸表/说明书 |
| 明确目标人群与营销场景 | 用【人群画像】【使用场景】【购买理由】区分**购买者**与**使用者**（可能不是同一类人）→ 提炼广告目标人群、图片场景、卖点顺序、节日/礼品/企业采购场景 |
| 辅助产品组合与备货 | 用网页版【评论型号统计】看不同尺寸/颜色的评论数量分布 |

### 4. 差评核对纪律

优先关注：
- 低星评论集中反映的问题；
- 是否有安全、质量或耐用性问题；
- 某个问题是否只出现在特定变体；
- 买家是否频繁提到退货、损坏或无法使用；
- 差评源于产品本身，还是说明不清、配送或使用方式；
- 相同问题是否在多个时间段持续出现。

> **某个问题只出现一次 → 不宜直接判断为普遍问题；相同问题在 AI 总结、Alexa 回答和多条真实评论中反复出现 → 更值得进一步验证。**

**AI 总结不能完全替代原声**。遇到严重差评、明显分歧或需确认细节时，必须切换到原声页签或网页版评论列表核对。

## 二、Listing 生成器与 Listing 诊断

| 工具 | 入口 | 用途 |
|---|---|---|
| Listing 生成器 | `/v3/listing-builder` | 基于关键词库与产品信息生成 Listing 文案（标题/五点/描述） |
| Listing 诊断 | `/v3/ai-history?module=LA` | AI 诊断现有 Listing 问题 |

### 埋词权重优先级

```
标题 > 五点描述 > 产品描述 > Search Terms > 其他
```

### Listing 优化闭环

```
关键词挖掘 → 关键词清洗（相关度 + Top10 产品图）→ 分库（核心词/长尾词）
        ↓
按权重优先级埋入 标题 → 五点 → 描述 → ST
        ↓
关键词监控（追踪自然排名与广告排名）
        ↓
关键词反查（检查是否被收录不相关词）
        ↓
AI 评论分析（买家误解点 → 反向修正 Listing 表达）
```

> **用评论反推 Listing 缺陷**是最被低估的一环：很多差评源于「Listing 表达不清导致预期偏差」，而非产品质量本身。
